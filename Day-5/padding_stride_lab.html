Padding and Stride Lab

Two settings decide the size of every feature map in a CNN. Padding adds a border so the image doesn't shrink and the edges aren't lost. Stride makes the filter jump, so the network gets faster and sees bigger patterns. Change them below and watch exactly what happens.

1. Why padding?

Without padding, a convolution has two problems. Both are easy to see.

Problem 1: the image shrinks after every layer

A filter of size f can only sit where it fits completely inside the image, so each layer loses f − 1 pixels in height and width. Stack layers and see what is left of a 28×28 MNIST digit.

3

Problem 2: border pixels are used less

Each number below counts how many filter positions cover that pixel (3×3 filter, stride 1, 6×6 image). More coverage means the pixel influences more of the output.

No padding (p = 0)

Corner pixel: used 1×. Centre pixel: used 9×. Information at the edges is under-used.

Zero padding (p = 1)

Every pixel takes part in more positions (corners 4×, the rest 6× or 9×), and the output stays 6×6.

Padding fixes both: add p rows and columns of zeros on every side. The padded image is n + 2p wide, so with stride 1 the output is n + 2p − f + 1. Choosing p = (f − 1) / 2 makes that exactly n: same padding.

3. Stride side by side

Same 7×7 image, same 3×3 filter, no padding. Only the stride changes.

Each cell shows how many times the filter covers it. Blue outlines mark where the window's top-left corner lands. Hatched cells are never covered at all.

Why use a stride larger than 1?
  1. Faster computation: fewer window positions, so fewer multiplications (see the counts above).
  2. Less training time and memory: smaller feature maps, and far fewer weights in the Dense layer after Flatten (section 5).
  3. Higher-level features: after downsampling, each pixel stands for a bigger area of the original image, so later layers learn larger patterns (shapes, object parts) instead of tiny edges.
The trade-off: with s = 3 the last row and column are skipped completely. (n − f) = 4 is not a multiple of 3, so the floor in the formula throws the leftover away. A big stride too early can lose useful detail.

Special case: stride 1

This is the padding formula from section 1.

Same padding: how much?

Set n + 2p − f + 1 = n and solve: p = (f − 1) / 2.

3×3 → 1, 5×5 → 2, 7×7 → 3. Padding is "usually 1" only because 3×3 filters are the most common.

7. Learning notes

What I learned

  • Without padding, every layer shrinks the image by f − 1, and border pixels are used less than centre pixels.
  • Zero padding adds p rings of zeros. p = (f − 1) / 2 keeps the size (same); p = 0 is valid.
  • Stride is how far the filter jumps. s = 2 roughly halves height and width.
  • A bigger stride is faster, uses less memory and parameters, and lets later layers see bigger patterns, but it can skip detail.
  • Conv layer parameters don't depend on image size. The Dense layer after Flatten does, which is where padding and stride change the model size.

Common mistakes

  • (n − f / s) + 1: divide the whole (n + 2p − f) by s.
  • Forgetting the 2 in 2p: padding goes on both sides.
  • Rounding up instead of down.
  • "Padding is always 1": it is (f − 1) / 2.
  • Thinking conv parameters grow with image size: they don't.

Self-test

1. A 32×32 image goes through a 5×5 filter with no padding and stride 1. What is the output size, and how much padding would keep it 32×32?

32 − 5 + 1 = 28, so 28×28. Same padding: p = (5 − 1) / 2 = 2.

2. Why is a corner pixel used only once by a 3×3 filter without padding?

The only window that contains the top-left pixel is the one whose top-left corner is that pixel. Any other position would need part of the window outside the image.

3. n = 9, f = 3, p = 0, s = 2. Output size? Is any pixel skipped?

⌊(9 − 3) / 2⌋ + 1 = 3 + 1 = 4. 9 − 3 = 6 is a multiple of 2, so nothing is skipped.

4. In the notebook, why does stride 2 in the first layer cut the parameters from 3.23 M to 0.82 M?

It halves height and width (28 → 14), so Flatten gives 14·14·32 = 6,272 numbers instead of 25,088. Each connects to 128 Dense neurons: 6,272·128 + 128 = 802,944 instead of 3,211,392. The conv layers stay at 320 + 9,248 + 9,248.

5. Give two reasons to use stride 2 and one risk.

Faster (fewer positions, fewer multiplications) and smaller (fewer parameters, less memory); later layers also see larger patterns. Risk: detail between positions is skipped, and leftover rows/columns can be ignored.
