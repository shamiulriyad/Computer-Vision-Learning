1. The problem we will solve

A 5×5 grayscale "image" and a 3×3 filter. Our goal: the feature map.

⊛

Blue cells are positive, red cells are negative, and darker means larger in size. The small grey numbers are row and column indices. They start at 0, like NumPy.

Before calculating anything: how big will the output be?

The 3×3 window must stay completely inside the 5×5 image. Its top-left corner can sit in columns 0, 1 or 2 (column 3 would push the right edge off the image), and the same for rows. That is 3 × 3 = 9 positions, so the feature map is 3×3. The formula gives the same answer:

The one equation behind everything

O[i][j] = Σm=0..F−1 Σn=0..F−1 I[i·S + m][j·S + n] × K[m][n]

Iinput image (after padding, if any)the 5×5 matrix above

O[i][j]output value at row i, column j of the feature map9 values, i, j ∈ {0, 1, 2}

In words: put the kernel on the image, multiply each pair of overlapping numbers, add the products, write down the result, slide, and repeat.

Read the kernel before you compute. Its left column is all +1, its middle column all 0, its right column all −1. So every output equals (sum of the window's left column) − (sum of the window's right column). That makes it a vertical edge detector: the answer is large when brightness changes from left to right. Section 2 uses this as an independent check.

2. The complete calculation, position by position

Nine filter positions, nine sums. Nothing skipped.

First, the big picture of a single step. The highlighted 3×3 region of the input is multiplied by the kernel and summed into exactly one cell of the feature map:

For every position we do the same six things:

  1. Extract the 3×3 region of the input under the window.
  2. Pair each region element with the kernel element in the same position.
  3. Multiply each pair (element-wise, ⊙) to get a 3×3 products matrix.
  4. Add all nine products.
  5. Store that single number in the output cell for this position.
  6. Slide the window by the stride and repeat until no valid position is left.

In the products matrix, the small grey text is the multiplication (region value × kernel value) and the large number is its result.

Result: the feature map

What do the numbers mean?

  • O[1][2] = 4 (largest): the window's left column (3, 1, 2) is brighter than its right column (1, 0, 1). That is a bright-to-dark edge going left to right.
  • O[0][1] = −4 (most negative): the right column (1, 2, 4) is brighter than the left (2, 1, 0). That is a dark-to-bright edge.
  • O[0][2] = 0: left and right columns have the same sum (4 and 4), so this filter finds no vertical edge there.

4. The concepts, each with numbers

Every idea below uses the same 5×5 input and kernel unless stated, so you can compare results directly.

AConvolution vs cross-correlation

What we computed in section 2 is, strictly speaking, cross-correlation: the kernel is laid on the image as it is.

Cross-correlation: O[i][j] = Σm Σn I[i + m][j + n] · K[m][n]

The mathematical (signal-processing) convolution first rotates the kernel by 180°, flipping it top-to-bottom and left-to-right, and then does the same multiply-and-add:

Convolution: O[i][j] = Σm Σn I[i + m][j + n] · K[F−1−m][F−1−n] (= cross-correlation with the flipped kernel)

Position 1 with the flipped kernel, to see where the sign change comes from:

Important: standard CNN implementations compute cross-correlation, without flipping the kernel, but everyone still calls it "convolution". PyTorch's nn.Conv2d documentation calls its operation cross-correlation, and OpenCV's cv2.filter2D documentation says it "does actually compute correlation, not the convolution". It does not matter for learning: the kernel weights are learned. If the flipped version is the useful one, gradient descent simply learns the flipped numbers. It does matter when you compare with a library that flips, such as scipy.signal.convolve2d; use scipy.signal.correlate2d instead. For symmetric kernels (box blur, Laplacian, sharpen) both give identical results.

BElement-wise multiplication (⊙)

Multiply numbers that sit in the same position: region[m][n] × K[m][n]. Nine independent multiplications, giving a matrix the same size as the kernel. This is the Hadamard product.

It is not matrix multiplication. Matrix multiplication (row × column) of the same two matrices gives something completely different:

For example, the top-left of the matrix product is row 0 of the region · column 0 of K = 1·1 + 2·1 + 0·1 = 3. In the element-wise product it is just 1·1 = 1.

In a real CNN layer each filter also has a bias b, added once after the sum: z = Σ(region ⊙ K) + b. With b = 1, position 1 would give −1 + 1 = 0. An activation such as ReLU is then applied to z (Day-3), but that is a separate step after the convolution.

DStride: S = 1 vs S = 2

The stride S is how many cells the window jumps each move, both to the right and down to the next row. The grids below number the window's top-left corner in visiting order. Each number is one output value.

With S = 2 the window lands at corners (0,0), (0,2), (2,0), (2,2). These are the same windows as positions 1, 3, 7 and 9 of the S = 1 run, so the stride-2 map is just every second value of the stride-1 map: −1, 0, −1, 1. Stride is a cheap way to downsample.

EPadding: P = 0 vs P = 1

Without padding (P = 0, "valid"), a 3×3 filter shrinks a 5×5 image to 3×3, and edge pixels take part in fewer windows than centre pixels. Zero padding adds P rings of zeros around the image first, so the window can also be centred on the border pixels.

The padded zeros contribute nothing to the sum (0 × anything = 0), so only the real pixels under the window count. Here is the corner position O[0][0] with P = 1:

"Same" padding: for an odd filter size F and S = 1, choosing P = (F − 1) / 2 keeps the output the same size as the input. So P = 1 for 3×3 and P = 2 for 5×5.

Padding and stride together: P = 1, S = 2

FOutput feature map dimensions

Output Size = ⌊(N − F + 2P) / S⌋ + 1
VariableMeaningWhy it is in the formula
Ninput size (height or width)the space available
Ffilter (kernel) sizethe window needs F cells, so the corner can only move N − F cells
Ppadding on each sideadds P cells on the left and P on the right, so 2P
Sstridethe corner moves S cells per jump, so we count jumps by dividing by S
⌊ ⌋floor (round down)a partial jump would push the window off the image, so it is not allowed

Derivation in one line: the padded input has N + 2P cells. The window's corner can go from 0 up to (N + 2P) − F. Counting positions in steps of S gives ⌊((N + 2P) − F) / S⌋ jumps, plus the starting position.

Use it separately for height and width. Example: a 5×7 input, F = 3, P = 0, S = 2 → height ⌊(5 − 3)/2⌋ + 1 = 2, width ⌊(7 − 3)/2⌋ + 1 = 3, so the output is 2×3.

GMultiple filters → multiple feature maps

One filter detects one kind of pattern and produces one feature map. A convolution layer runs K different filters over the same input and stacks the K feature maps into an output volume of depth K.

Filter 1 responds to vertical edges and filter 2 to horizontal edges. Look at O[1][2]: 4 for vertical, 3 for horizontal. That region has both kinds of change.

Output volume = Hout × Wout × (number of filters) → 3 × 3 × 2
Parameters = (number of filters) × (F × F × C + 1) → 2 × (3 × 3 × 1 + 1) = 20

C = number of input channels (1 for grayscale, 3 for RGB). The +1 is each filter's bias.

Going further: a multi-channel input

For an RGB image every filter is F × F × C. Each channel is multiplied by its own kernel slice, all the products of all channels are added, plus one bias, giving one number. A 2-channel example (2×2 kernel slices, bias = 1):

7. Learning notes

What I learned

  • A convolution layer slides a small kernel over the input. At each position it multiplies element-wise, sums, and writes one number.
  • The collection of those numbers is the feature map. Large values mean "the pattern this kernel describes is here".
  • The kernel (+1, 0, −1) per row computes left-column minus right-column, so it is a vertical edge detector.
  • Stride controls the jump size and therefore the output resolution. Padding controls what happens at the borders and can keep the size unchanged.
  • CNN libraries compute cross-correlation (no kernel flip), and call it convolution.
  • K filters give K feature maps, stacked into a volume of depth K. With C input channels, each filter is F×F×C and all channel products are added together.

Important formulas

O[i][j] = ΣmΣn I[i·S+m][j·S+n]·K[m][n] + b
Out = ⌊(N − F + 2P) / S⌋ + 1
Same padding: P = (F − 1) / 2 (S = 1, F odd)
Padded size = N + 2P
Params = K × (F·F·C + 1)
Output volume = OutH × OutW × K

Common mistakes

  • Doing matrix multiplication (row × column) instead of element-wise multiplication.
  • Losing a minus sign: 3 × (−1) = −3. Write every product with its sign before adding.
  • Flipping the kernel when the question means CNN "convolution". CNNs do not flip.
  • Forgetting the +1 in the output-size formula, or forgetting the 2 in 2P.
  • Rounding up instead of down when (N − F + 2P) is not divisible by S.
  • Moving by 1 when the stride is 2, in both directions: also when jumping to the next row.
  • Computing on the unpadded image when P > 0. Pad first, then slide.
  • Writing the result in the wrong output cell. Output (i, j) comes from the window whose corner is (i·S, j·S).

Five self-assessment questions

1. A 7×7 input, 3×3 kernel, P = 0, S = 2. What is the output size, and where are the window corners?

⌊(7 − 3 + 0)/2⌋ + 1 = ⌊2⌋ + 1 = 3, so 3×3. The corners are at rows {0, 2, 4} × columns {0, 2, 4}, 9 positions in total.

2. Region [[2, 0, 1], [1, 3, 0], [4, 1, 2]] and kernel [[1, 0, −1], [1, 0, −1], [1, 0, −1]]. What is the output value?

Products: [[2, 0, −1], [1, 0, 0], [4, 0, −2]]. Sum = 2 + 0 − 1 + 1 + 0 + 0 + 4 + 0 − 2 = 4. Shortcut check: left column 2 + 1 + 4 = 7, right column 1 + 0 + 2 = 3, and 7 − 3 = 4.

3. Why do PyTorch and TensorFlow not flip the kernel, and when would the flip matter?

The weights are learned, so the network can learn the flipped kernel directly. Flipping adds work and changes nothing about what can be learned. It matters when you copy a hand-designed kernel between tools that disagree, for example scipy.signal.convolve2d (flips) vs cv2.filter2D (does not). For non-symmetric kernels the results then differ; for the Day-4 kernel, every sign flips.

4. You need a 32×32 input to stay 32×32 after a 5×5 convolution with S = 1. What padding do you need?

"Same" padding: P = (F − 1)/2 = (5 − 1)/2 = 2. Check: ⌊(32 − 5 + 4)/1⌋ + 1 = 31 + 1 = 32.

5. An RGB 64×64 image goes through a layer with 16 filters of 3×3, P = 1, S = 1. Give the output volume and the number of parameters.

Spatial size: ⌊(64 − 3 + 2)/1⌋ + 1 = 64. The output volume is 64 × 64 × 16, one feature map per filter. Parameters = 16 × (3·3·3 + 1) = 16 × 28 = 448.
